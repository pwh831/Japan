## 1. 개요

### 1.1 배경

일본어 시험범위를 반복해서 외우고 스스로 시험 볼 도구가 필요하다. 종이 교재는 답이
옆에 보여서 "아는 것 같은 느낌"만 남고, 실제로 쓸 수 있는지는 확인되지 않는다.
**직접 입력해서 틀리는 것을 확인하는** 것이 이 프로그램의 핵심이다.

같은 사용자가 쓰는 `Jiri`(지역이해 암기 퀴즈)와 동일한 구조 — 빌드 도구 없는 단일
HTML + 데이터 파일 + localStorage — 를 따른다. 검증된 틀이므로 새로 설계하지 않는다.

### 1.2 목표

- 시험범위를 **세 갈래로 나눠** 각각에 맞는 방식으로 훈련한다(§3).
- 쓰는 훈련은 반드시 **직접 타이핑·필기**로 확인한다. 보기에서 고르는 것으로는 시험에서 못 쓴다.
- **히라가나로 쓰는지 가타카나로 쓰는지**를 틀리면 틀렸다고 잡아 준다.
- 틀린 항목을 자동으로 추적해 맞을 때까지 반복 노출시킨다.
- 태블릿에서 **애플펜슬로 직접 써서** 답을 넣을 수 있게 한다.

### 1.3 비목표

- **한자 쓰기** — 교재가 단어를 가나로만 적는다. 한자는 나오지 않는다(§4.1.1).
- **앱 내장 손글씨 인식기** — OS(`手書き`·스크리블)가 이미 한다. 앱은 방해하지 않는 것만 책임진다.
- 문법 설명·독해·청해 문제
- 음성 재생(TTS)·발음 평가
- 다중 사용자 계정 / 서버 로그인 / 클라우드 동기화
- AI 자동 문제 생성 — 데이터는 교재 기반 수기 입력

### 1.4 성공 기준

- 세 시험을 각각 따로 풀 수 있고, 진도도 따로 쌓인다.
- 오답 항목이 정답 처리될 때까지 반복 출제된다.
- 가타카나로 써야 할 것을 히라가나로 쓰면 오답으로 잡히고, 그 이유를 알려 준다.
- 일본어 키보드가 없는 아이패드에서도 답을 넣을 수 있다.
- 한 세션(20문항)을 5분 안에 풀 수 있다.

## 2. 사용자

| 구분 | 설명 |
|---|---|
| 주 사용자 | 일본어 수업 수강생 본인 (단일 사용자) |
| 사용 환경 | 태블릿·휴대폰 우선(통학 중 학습), PC 브라우저도 지원 |
| 사용 시점 | 시험 2~3주 전부터 매일 10~20분 |

**핵심 사용자 스토리**

1. 오늘은 단어만, 내일은 동사 활용만 — 갈래를 골라서 풀고 싶다.
2. 뜻을 보고 일본어를 **직접 써 보고** 맞았는지 확인하고 싶다.
3. 히라가나로 쓰는지 가타카나로 쓰는지를 자꾸 헷갈리는데, 그걸 짚어 줬으면 좋겠다.
4. `どこか` 와 `どこが` 처럼 **교재가 나란히 놓고 비교시키는 것**을 확실히 가르고 싶다.
5. `かえる` 가 왜 1류인지 매번 헷갈린다. 예외만 모아서 반복하고 싶다.
6. 태블릿에서 애플펜슬로 쓰면 그대로 들어가면 좋겠다. 시험도 손으로 쓰니까.
7. 틀린 것만 모아서 다시 풀고 싶다.

## 3. 세 시험

| # | 시험 | 무엇을 묻나 | 데이터 | 현황 |
|---|---|---|---|---|
| 1 | **단어** | 낱말의 뜻과 표기 | `data/words.js` · 66항목 | ✅ 완성 |
| 2 | **표현** | 문장을 언제·어떻게 쓰나 | `data/phrases.js` · 10항목 | ✅ 완성 |
| 3 | **동사 활용** | 활용 **규칙** | `data/verbs.js` · 25동사 | ✅ 완성 |

### 3.1 왜 나누는가

**세 가지는 외우는 방식이 다르고, 그래서 숙달 판정이 다르게 돌아야 한다.**

- **단어**는 항목을 외우면 끝이다. `たべもの` 를 안다고 `のみもの` 를 아는 것이 아니다.
- **표현**은 문장이라 통째로 타이핑하기엔 길고, 정작 중요한 건 **언제 쓰는가**와
  **헷갈리는 짝과의 구별**이다. 단어와 같은 유형으로는 그것이 안 잡힌다.
- **활용**은 규칙을 익히는 것이다. `いく` 를 맞혔다고 `のむ` 를 맞히는 것이 아니고,
  반대로 규칙을 알면 **안 배운 동사도 맞힌다.**

셋을 한 통계에 섞으면 전부 흐려진다. "단어 80%"라는 숫자가 단어를 아는 것인지
규칙을 아는 것인지 알 수 없게 된다. 그래서 진도·오답 노트·숙달을 시험별로 따로 센다.

### 3.2 무엇을 공유하는가

세 시험은 **한 앱 안의 세 모드**다. 아래를 함께 쓴다.

- 채점기 (§7) — 가나 정규화, 가나 종류 판정, 혼동쌍 되묻기
- 일본어 입력 (§8) — 손글씨·로마자 변환·화면 자판
- 오답 우선 출제·반복 규칙 (§9) — 규칙은 같고 통계만 분리
- 화면 껍데기 — 원고지 입력칸, 결과 화면, 진도 막대

따로 가는 것은 **데이터 모양 · 문제 유형 · 숙달 판정** 셋뿐이다.

## 4. 시험 1 · 단어

### 4.1 데이터

```jsonc
{
  "id": "j605",
  "unit": "006a",              // 범위 선택 단위 (쪽·절)
  "pos": "동사",                // 명사 | 동사 | い형용사 | 부사 | 조사 | 접속 | 표현
  "word": "みる",               // 교재 표기 그대로
  "kana": "みる",               // **정답 기준.** 교재가 가나로만 적으므로 word와 같다
  "meaning": ["보다"],          // 첫 번째가 대표 뜻
  "jaAliases": [],             // 추가로 인정할 표기 (「～」 붙은 항목 등)
  "examples": [{ "ja": "…", "ko": "…", "form": "みる" }],
  "note": "지명"                // 보조 설명(선택)
}
```

**필수 필드**: `id` · `unit` · `word` · `kana` · `meaning`.
`kana` 는 정답 기준이므로 교재 표기를 **글자 하나까지 그대로** 옮긴다.
장음 `ー`, 촉음 `っ`, 탁점, 히라가나/가타카나 구분이 전부 채점에 쓰인다.

**`jaAliases` 는 반드시 채점에 넘어가야 한다.** 「～けど」 처럼 물결표가 붙은 교재
표기를 그대로 써도 정답이어야 한다. 채점기에 합성 객체를 넘기면 이 필드가 죽는다
(§17에서 실제로 그랬다). 회귀 테스트로 고정되어 있다.

#### 4.1.2 유형 C 의 빈칸 불변식

예문에서 **표제어(`word`)가 문장 안에 그대로 있을 때만** 유형 C 에 쓴다.
빈칸은 그 단어가 나온 자리를 **전부** 가린다.

- 첫 자리만 가리면 `はやく、はやく!` 처럼 두 번 나오는 문장에서 정답이 그대로 보인다.
- 「～けど」·「まもります」 처럼 표제어가 문장에 없는 항목은 빈칸과 보기가 아귀가
  안 맞으므로 **C 에서 뺀다.** A·B 에는 그대로 나온다.

이 규칙으로 66단어 중 **36단어**가 유형 C 에 나온다. `examples` 의 `form` 필드는
참고용이며 빈칸을 파는 데 쓰지 않는다.

#### 4.1.1 교재에서 확인된 것

- **한자가 아예 없다.** 단어가 전부 가나로 적혀 있어 `word` 와 `kana` 가 같다.
- **가타카나 단어는 5개뿐** — `バス`·`アニメ`·`プール`·`ぼうさいセンター`·`ドア`.
  혼동쌍 글자는 `ぼうさいセンター` 의 `ン` 하나이므로 오인식(§8.4) 위험이 작다.
- **102쪽은 `ます`형, 100쪽은 기본형**으로 실려 있다. 교재 표기를 그대로 따라 섞지 않는다.
- 예문 42개는 전부 본문 대화와 `보기` 에서 가져왔다. **지어내지 않았다.**

### 4.2 문제 유형

| 유형 | 형태 | 비중 |
|---|---|---|
| **A** 뜻 고르기 | `みる` → 뜻 5지선다 | 30% |
| **B** 직접 쓰기 | "보다" → `みる` 타이핑 | **50%** |
| **C** 예문 빈칸 | `ともだちと アニメを ____ よていだよ。` | 20% |

- B가 핵심이다. 시험 대비 효과가 가장 크므로 비중을 가장 높게 잡는다.
- A의 오답 보기는 **같은 품사**의 다른 단어 뜻에서 뽑고, 정답 단어의 다른 뜻과
  겹치는 문구는 제외한다(정답이 둘이 되는 사고 방지).
- C는 §4.1.2의 불변식을 만족하는 단어만 출제된다. 66개 중 **36개**.
- 힌트는 2단계 — 1단계 글자 수(`○○○`), 2단계 첫 글자(`み○`).
  첫 글자를 열면 가나 종류까지 드러나므로 한 단계 앞에 둔다.

### 4.3 숙달 판정

**유형 B 연속 3회 정답.** 뜻만 아는 단어를 숙달로 넘기지 않기 위해서다.

## 5. 시험 2 · 표현

### 5.1 왜 단어와 다른가

표현은 **문장**이라 통째로 타이핑하기엔 길다. 그리고 정작 시험에 나오는 것은
문장을 통째로 재현하는 능력이 아니라 **언제 쓰는가**와 **헷갈리는 짝과의 구별**이다.

교재가 105·107쪽 `정리하기` 에서 `どこか` vs `どこが` 를 나란히 놓고 비교시키는 것이
그 신호다. 붙여 놓고 비교시키는 것은 내겠다는 뜻에 가깝다.

### 5.2 데이터

```jsonc
{
  "id": "p105a",
  "unit": "006x",                       // 쪽·절
  "kind": "대비",                        // 대비 | 표현 | 전개
  "ja": "どこか いく?",                   // 표현 문장
  "ko": "어딘가 갈까?",
  "use": "정해지지 않은 곳을 물을 때",      // 언제 쓰는가 — 시험 2의 핵심 필드
  "key": "どこか",                        // 이 표현을 이 표현이게 하는 부분 (빈칸·정답)
  "vs": {                               // kind가 "대비"일 때만
    "ja": "どこが いい?",
    "ko": "어디가 좋아?",
    "key": "どこが",
    "why": "どこか 는 '어디인가', どこが 는 '어디가'"
  },
  "note": "105쪽 정리하기 1"
}
```

`key` 가 단어 시험의 `kana` 에 해당한다 — **채점 대상은 문장 전체가 아니라 `key` 다.**

### 5.3 범위 (수령분 10항목)

| 출처 | 항목 | `kind` |
|---|---|---|
| 98쪽 의사소통 기본 표현 | `こんどの しゅうまつ、なに する?` (상황 설명) | 표현 |
| | `ぼうさいセンターは どうやって いくのかな?` (방법·이유) | 표현 |
| | `まず、あたまと からだを まもりましょう。` (지시) | 표현 |
| | `それから?` (화제 전개) | 전개 |
| | `あぶない!` (주의 환기) | 표현 |
| 105쪽 정리하기 1 | `どこか` ↔ `どこが` | **대비** |
| | `～から` — 때문에(이유) ↔ 에서(출발·기점) | **대비** |
| | `どうやって いくの?` (방법) | 표현 |
| 107쪽 정리하기 2 | `はい、そうです。` ↔ `いいえ、ちがいます。` | **대비** |
| | `まず … それから …` (화제 전개) | 전개 |

### 5.4 문제 유형

| 유형 | 형태 |
|---|---|
| **D** 대비 고르기 | `____ いく?` — `どこか` / `どこが` 중 문맥에 맞는 것. **`kind:"대비"` 전용** |
| **E** 뜻 고르기 | `あぶない!` → 뜻 5지선다 |
| **F** 상황 → 표현 | "주의를 줄 때 뭐라고 하나?" → 표현 5지선다 |
| **G** 핵심어 쓰기 | `こんどの しゅうまつ、____ する?` → `なに` 를 직접 쓴다 |

배분은 **D 35 / G 25 / E 20 / F 20.**

- **D가 이 시험의 이유다.** 나머지 셋만이면 단어 시험과 다를 게 없다.
- **D 에서는 한국어 뜻을 보여 주지 않는다.** 「어딘가 갈까?」를 같이 띄우면 답이
  그대로 새어 나간다. 일본어 문맥만으로 가르게 둔다 — `____ いく?` 인지 `____ いい?`
  인지, `はい、____` 인지 `いいえ、____` 인지가 곧 단서다.
- G는 문장 전체가 아니라 `key` 만 쓴다. 통째로 쓰게 하면 길어서 안 하게 된다.
- **문장이 곧 `key` 인 항목은 G 에서 뺀다.** 「それから?」 는 빈칸을 파면 `____?` 가
  되어 물어볼 것이 없다. 13개 면 중 11개가 G 에 나온다.
- F 는 본문 쪽만 낸다. `use`(언제 쓰는가)는 짝 쪽에 없기 때문이다.
- **문장 전체 타이핑도, 낱말 카드 배열도 하지 않는다.** 105쪽에 카드 배열 문제가
  실려 있어 한때 후보였으나, `key` 쓰기만으로 좁혔다(§16 Q3).

### 5.5 숙달 판정

**`kind:"대비"` 는 유형 D 를 양쪽에서 각각 연속 3회.** 한쪽만 3회 맞혀서는 숙달이
아니다 — `どこか` 만 계속 맞히고 `どこが` 를 못 고르면 가른 것이 아니기 때문이다.
통계도 `D`(본문)와 `D1`(짝)로 따로 센다.

나머지는 **유형 G 연속 3회.** G 에 못 나오는 항목(§5.4)은 유형 E 로 센다.

## 6. 시험 3 · 동사 활용

### 6.1 근거

107쪽 `정리하기 2` 에 **동사 활용표**가 실려 있다 — "동사의 기본형은 [u]단으로 끝난다"
와 `いく`/`いきます`/`いきましょう` 6줄. 103쪽 연결 문제도 `ましょう` 형만 다루고,
100쪽 필기에는 단어마다 1류·2류·3류가 적혀 있다. **활용은 시험 범위다.**

### 6.2 데이터 — 활용형은 적지 않는다

동사마다 **그룹만** 있으면 활용형은 규칙으로 만들어진다. 표를 손으로 옮기지 않는다.

```jsonc
{
  "id": "v613",
  "kana": "かえる",
  "meaning": ["(집에) 돌아가다"],
  "group": 1,            // 1 | 2 | 3
  "tricky": true,        // る로 끝나 2류처럼 보이지만 1류 — 더 자주 낸다
  "wordId": "j613"       // 시험 1의 같은 단어 (있으면)
}
```

**어간(연용형) 하나에서 세 형이 전부 나온다.**

| 그룹 | 어간 구하기 | 어간 | `ます` | `ましょう` | `たい` |
|---|---|---|---|---|---|
| 1류 (5단) | 어미 [u]단 → [i]단 | `いき` | いきます | いきましょう | いきたい |
| 2류 (1단) | `る` 뗀다 | `たべ` | たべます | たべましょう | たべたい |
| 3류 (불규칙) | 외운다 | `き` · `し` | きます | きましょう | きたい |

그래서 `たい` 가 범위에 들어와도 **데이터는 한 줄도 안 늘었다.** 어간 함수 하나에
접미사 표만 붙이면 된다.

> **`ましょう` 를 남긴 이유**: 동사테스트 탭에는 `ます`·`たい` 둘뿐이다(§16 Q7).
> 그래도 남긴 것은 107쪽 정리하기 표에 `ましょう` 열이 있고, 103쪽 연결 문제가
> 통째로 `ましょう`형이며, 102·103쪽 `ことば` 에 `まもりましょう`·`あらいましょう`·
> `でましょう` 가 단어로 실려 있기 때문이다. 교재가 그만큼 다루는 것을 빼면
> 시험에 나왔을 때 손해다.

#### 6.2.1 예외를 반드시 데이터로 표시한다

`かえる` · `はいる` 는 `る` 로 끝나 2류처럼 보이지만 **1류**다.
규칙만 믿고 자동 판정하면 `かえます` 라는 **틀린 답을 정답으로 채점한다.**
100쪽 필기에도 `예외` 표시가 있다. `group` 은 반드시 데이터에 명시하고,
`tricky:true` 인 항목은 출제 가중치를 올린다.

### 6.3 범위 (수령분 25동사)

| 그룹 | 수 | 동사 |
|---|---|---|
| 1류 | 16 | `あらう` `のむ` `いく` `よむ` `やすむ` `はなす` **`かえる`** `のる` `あそぶ` `さそう` `まもる` **`はいる`** `しゃがむ` `まつ` `けす` `よぶ` |
| 2류 | 6 | `おきる` `たべる` `みる` `ねる` `でる` `あける` |
| 3류 | 3 | `くる` `する` `べんきょうする` |

**굵은 글씨 2개가 `tricky` 예외**다.

### 6.4 문제 유형

| 유형 | 형태 | 비중 |
|---|---|---|
| **H** 활용형 쓰기 | `いく` → `たい`형은? → `いきたい` 를 직접 쓴다 | **60%** |
| **I** 그룹 고르기 | `かえる` 는 1류·2류·3류 중? → **예외를 잡아내는 유형** | 25% |
| **J** 기본형 되찾기 | `きます` 의 기본형은? → `くる` | 15% |

**발문은 기본형에서 출발한다.** "`いく` → `ます`형은?" 이지 "'갑니다'를 일본어로?" 가
아니다. 뜻에서 출발하면 시험 1의 유형 B와 구별이 사라지고, 활용은 "규칙을 적용하는가" 를
묻는 것이지 "뜻을 아는가" 를 묻는 것이 아니다. 한국어 뜻은 아래에 작게만 보여 준다.

**H 안에서 세 형의 배분은 `たい` 40 / `ます` 30 / `ましょう` 30.**
`たい` 만 107쪽 교재 표에 없었는데 실제 시험에는 나왔다. 가장 덜 다뤄진 형이므로
가장 많이 낸다.

- I는 `tricky` 항목을 집중적으로 낸다. 여기가 이 시험에서 제일 많이 틀릴 곳이다.
- 채점은 §7을 그대로 쓴다 — 가나 표기, 엄격 판정, 혼동쌍 되묻기.
- 해설에는 **활용표를 통째로** 보여 준다(기본형·`ます`·`ましょう`·`たい`, 물은 형을 강조).
  한 문제를 풀 때마다 규칙이 눈에 남는다.

### 6.5 숙달 판정 — 규칙 단위로도 본다

단어와 다르다. **항목별 숙달과 규칙별 숙달을 함께 센다.**

- 항목: 세 형(`ます`·`ましょう`·`たい`)을 **각각** 연속 3회 → 그 동사 숙달
- 규칙: **1류 `たい`형** 처럼 (그룹 × 형) 조합을 **서로 다른 동사로** 연속 5회 → 규칙 숙달
  - 같은 동사를 반복해서는 오르지 않는다. 규칙을 아는 것과 한 단어를 외운 것은 다르다.

규칙이 숙달되면 그 그룹의 평범한 동사는 출제 가중치를 낮추고, `tricky` 항목만 남긴다.
규칙을 아는데 25개를 하나씩 다 물어보는 것은 시간 낭비이기 때문이다.

## 7. 공통 · 채점 규칙

### 7.1 정답 기준은 가나

시험범위가 히라가나·가타카나 표기만 요구하므로, 한자를 쓸 수 있는지는 채점하지 않는다.
한자로 써도 정답으로 친다 — 더 어려운 답을 틀렸다고 할 이유가 없다.

### 7.2 가타카나와 히라가나는 엄격히 구분한다

어느 쪽으로 쓰는 단어인지 아는 것이 이 시험의 핵심 능력이다.
`テレビ` 를 `てれび` 로 쓰면 **오답**이다.

다만 다른 오답과 똑같이 처리하지 않는다. 글자는 다 맞고 가나 종류만 틀렸을 때는
**"가나 종류가 다릅니다 — 이 단어는 가타카나로 씁니다"** 라고 짚어 주고 다시 쓰게 한다.
아는 것을 몰라서 틀린 것과 표기 규칙을 헷갈려 틀린 것은 다시 봐야 할 지점이 다르다.

### 7.3 정규화 — 여기까지만 관대하게 본다

1. 앞뒤·중간 공백 전부 제거
2. 전각/반각 통일 (`ｱ` → `ア`), 결합 탁점(`ｶﾞ` → `ガ`) 정규화
3. 문장 부호(`。` `、` `･`) 제거
4. 한국어 뜻 쪽 괄호 주석은 문제로 낼 때 미리 뗀다

**그 밖에는 교재 표기와 글자 단위로 같아야 한다.** 장음 `ー`, 촉음 `っ`, 탁점,
작은 가나까지 전부 채점 대상이다. 표기가 둘 이상 통용되면 `jaAliases` 에 적는다.

> **v0.1에서 뒤집은 것**: 처음에는 가타카나를 히라가나로 통일해 비교하고 장음 `ー` 와
> 모음 반복을 같게 보려 했다. 시험이 **가나 표기 자체를 묻는다**는 것이 확인된 이상
> 둘 다 틀린 설계다. 정답을 오답으로 만들 걱정보다, **틀린 표기를 정답이라고 알려 줄
> 위험**이 크다.

### 7.4 오타는 봐주지 않는다

`Jiri` 는 편집거리 1까지 정답으로 봤지만, 일본어는 촉음(`きって`/`きて`)·탁점·장음
한 글자가 다른 단어다. 대신 **"거의 맞았습니다 — 한 글자만 다릅니다"** 라고 알려 주고
**다시 쓰게** 한다(오답 기록은 남긴다).

### 7.5 혼동쌍은 되묻는다

`コ`/`ユ`, `シ`/`ツ`, `ソ`/`ン`, `ク`/`タ`, `ス`/`ヌ`, `ン`/`リ`, `ノ`/`メ`, `ワ`/`ク`,
`チ`/`テ`, `ヲ`/`ラ` — 자형이 닮아 손글씨 인식이 자주 뒤바꾸는 짝이다.

입력이 목표와 **혼동쌍 하나만큼만** 다를 때는 바로 오답 처리하지 않고
"`ユ` 로 인식됐습니다. 이렇게 쓰신 게 맞나요?" 라고 되묻는다.
`맞다` 면 오답, `아니다` 면 기록 없이 다시 쓴다.

**내가 틀린 것인지 기계가 못 읽은 것인지는 쓴 사람만 안다.** 그러니 앱이 대신
판단하지 않고 물어본다.

## 8. 공통 · 일본어 입력

시험이 손으로 쓰는 시험이므로, 연습도 손으로 쓰는 것을 기본으로 한다.
세 방식을 나란히 두고 고르게 한다.

### 8.1 OS 손글씨 (태블릿) — 앱이 만들 것은 없다

아이패드 일본어 키보드의 `手書き` 모드 또는 스크리블. 인식은 OS가 한다.
앱 입장에서는 **평범한 텍스트 입력창**이므로 할 일은 "방해하지 않는 것"뿐이다.

- 입력 이벤트를 가로채거나 키 입력을 직접 조립하지 않는다
- 자체 키보드를 강제로 띄우지 않는다 (`readonly` + 커스텀 입력 금지)
- 조합 중인 문자를 `compositionstart`~`compositionend` 사이에 건드리지 않는다
  (조합 중 값을 읽어 채점하면 반쪽짜리 가나를 오답 처리한다)
- 입력창 아래 여백을 둬서 손글씨 패널이 문제를 가리지 않게 한다

### 8.2 로마자 → 가나

`tabemono` → `たべもの`. 헵번식·훈령식 둘 다 받고 촉음·요음·발음·장음을 처리한다.

**가타카나 전환은 사용자가 직접 누른다.** 자동 판별하지 않는다 —
어느 가나로 쓰는 단어인지 고르는 것이 곧 답의 일부이기 때문이다.

말끝 `n` 은 타이핑 중에는 남겨 두고(`na` 를 칠 수 있어야 하므로) **제출 때 `ん` 으로
굳힌다.** 이 처리를 빠뜨리면 `hon` 이 `ほn` 으로 채점된다.

### 8.3 화면 가나 자판  ⏳ 미착수 (M11)

50음도 팔레트 + 탁점·반탁점·작은 글자. 펜도 로마자도 여의치 않을 때의 대비책.

### 8.4 오인식은 있다

실기기 점검에서 `コ` 를 썼는데 `ユ` 로 들어오는 일이 관측됐다.
빈도는 재지 못했다. 대신 **빈도를 몰라도 되게** 만들었다 — 로마자 입력을 나란히
기본 선택지로 넣었다. `ko` 는 규칙상 `ユ` 가 될 수 없으므로, 손글씨가 얼마나 흔들리든
확실한 길이 항상 하나 열려 있다. 측정에 시간을 더 쓰는 대신 측정이 필요 없는 설계를 골랐다.

손글씨를 쓸 때를 위해 §7.5의 되묻기를 둔다.

> `手書き` 키보드가 스크리블보다 안전하다. 후보 목록을 띄워 주므로 확정 전에 고를 수
> 있다. 스크리블은 후보 없이 바로 꽂으므로 오인식이 소리 없이 지나간다.

## 9. 공통 · 오답 노트와 진도

규칙은 세 시험이 같고, **통계만 분리한다**(§3.1).

- 항목별 상태: `정답 횟수` · `오답 횟수` · `연속 정답(유형별)` · `가나 종류 오류` · `마지막 학습일`
- **가중 출제**: 미학습 > 최근에 틀린 것 > 오답 많은 것 순
- **졸업**: 시험별 숙달 규칙(§4.3 · §5.5 · §6.5)을 만족하면 가중치 최소화
- **가타카나 오답 모아보기** ⏳ 미착수 (M12): 가나 종류를 틀린 항목만 따로 묶는다.
  `kanaErr` 는 이미 세고 있으나 아직 어디서도 읽지 않는다
- 진도 대시보드: 시험별 `미학습 / 학습중 / 숙달`.
  **범위별 세분은 ⏳ 미착수 (M13)** — 지금은 시험 단위 합계만 보여 준다
- 기록은 브라우저 `localStorage` 의 `jp-exam-v2` 한 키에
  `{ word:{…}, verb:{…}, phrase:{…}, rules:{…} }` 로 담는다.
  `rules` 는 시험 3의 (그룹 × 형) 연속 정답이다.
- **v1 기록은 버리지 않고 옮긴다.** 옛 키 `jp-vocab-v1` 이 있으면 첫 실행 때
  `word` 칸으로 한 번 이전한다. 버리면 오답 우선 출제가 처음부터 다시 시작한다.
  v2 블롭을 읽을 때는 **칸이 하나라도 있으면 받아들이고 빠진 칸만 채운다.**
  `word` 유무로만 판단하면 동사만 푼 기록을 통째로 버린다.
- 기록 지우기는 **지금 보고 있는 시험만** 지운다.

## 11. 기술 스택

`Jiri` 와 동일하다. 새로 정할 것이 없다.

- HTML + 바닐라 JavaScript, 빌드 도구·의존성 없음
- 데이터: `data/words.js` · `data/verbs.js` · `data/phrases.js` — 파일 하나에 시험 하나
- 저장: `localStorage`
- 배포: `python3 build.py` 로 데이터까지 인라인한 **단일 HTML** 을 만들어 Artifact로 발행
  (아이패드는 내려받은 HTML을 브라우저로 여는 길이 막혀 있다)

> **데이터 파일이 늘면 `build.py` 의 `DATA` 목록에 반드시 추가한다.**
> 빠뜨리면 산출물에 `<script src="…">` 가 남고, 파일 하나만 옮겼을 때 그 변수가
> `undefined` 가 되어 **앱 전체가 죽는다**(홈의 시험 고르기조차 안 뜬다).
> `build.py` 는 산출물에 외부 스크립트가 하나라도 남으면 **빌드를 실패시킨다.**
> `data/phrases.js` 를 넣을 때 실제로 이 단언에 걸려 목록을 갱신했다.

## 18. 시험 2 구현 메모 (M7)

설계(§5)를 그대로 옮기면서 코드가 강제하게 만든 것 셋.

- **`phraseDataErrors()`** — `key` 가 문장 안에 없으면 빈칸을 팔 수 없다. 짝의 `key` 가
  같으면 고를 수가 없다. `use` 가 없으면 유형 F 를 못 낸다. 이런 것들을 데이터 검증기가
  능동 감시하고 테스트가 매번 부른다(§6.2.1의 `verbDataErrors` 와 같은 방식).
- **`sideOf`·`sides`·`gOk` 를 테스트되는 구역에 뒀다.** 대비 항목의 양면과 G 출제
  가능 여부는 데이터 계약이지 UI 사정이 아니다. `extract-engine.py` 가 떼어 가는
  구역에 있어야 node 로 검증된다.
- **D 의 답 노출을 테스트로 막았다.** 브라우저 시험이 대비 문제마다 화면에 한국어가
  없는지 확인한다. 뜻을 친절히 띄우고 싶어지는 자리라, 코드가 아니라 테스트로 묶었다.

## 17. 독립 비평 기록 (devils-advocate, 2026-09-10)

v1.1을 독립 서브에이전트에게 22항목 이분법 비평을 받았다. **15/22 통과, 7건 실패.**
문서를 쓴 사람이 스스로 채점하면 빈틈을 머릿속에서 메우므로 남에게 맡겼다.

### 잡아낸 것 중 가장 큰 것

**배포본이 혼자서는 죽었다.** `build.py` 가 `words.js` 하나만 인라인해서 산출물에
`<script src="data/verbs.js">` 가 남았고, 파일 하나만 옮기면 `VERBS is not defined` 로
**앱 전체가** 죽었다(홈의 시험 고르기조차 안 떴다).

더 뼈아픈 것은 **검증이 그것을 못 잡은 이유**다. `smoke.js` 가 산출물을 저장소
루트에서 열어 `data/verbs.js` 가 상대 경로로 우연히 잡혔다. 테스트는 통과했지만
테스트가 검증한 것이 배포되는 물건이 아니었다. 지금은 빈 임시 디렉터리에 복사해서
연다(§11).

### 7건과 처리

| 항목 | 결함 | 처리 |
|---|---|---|
| `imports-correct` | 배포본에 외부 스크립트가 남아 앱 사망 | `build.py` 를 데이터 목록 루프로 바꾸고, 외부 `src` 가 남으면 **빌드 실패** |
| `follows-patterns` | 같은 원인. 세 번째 데이터 파일에서 또 깨질 구조 | §11에 규칙 명문화 + 빌드 단언 |
| `no-hacky-shortcuts` | v1 저장 계층이 죽은 채 같은 스코프에 중복 선언 | 잔재 삭제. `smoke.js` 를 빈 디렉터리에서 열게 변경 |
| `types-consistent` | 채점에 합성 객체를 넘겨 `jaAliases` 6건이 죽음 — 「～けど」 가 오답 | 단어 시험은 항목을 그대로 넘긴다. 회귀 테스트 12개 추가 |
| `edge-cases` | 유형 C 빈칸이 `form`/`word` 불일치와 중복 출현에서 깨짐 | §4.1.2 불변식 신설. 66→36단어로 좁히고 전 자리 가림 |
| `req-coverage` | 가나 자판·오답 노트·범위별 진도가 요구사항뿐 | M11~M13으로 올리고 본문에 ⏳ 표시 |

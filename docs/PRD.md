- 문서 버전: v0.2
- 작성일: 2026-09-10
- 상태: **학습지·교재 미수령** — 데이터 0항목, 설계만 확정

  입력 방식을 **애플펜슬 손글씨 중심**으로 재편했다 (§5.2 · §6.4)

## 1. 개요

### 1.1 배경

일본어 시험범위에 나오는 단어를 반복해서 외우고, 실제 시험과 같은 방식으로
스스로 시험 볼 도구가 필요하다. 종이 단어장은 답이 옆에 보여서 "아는 것 같은 느낌"만
남고, 실제로 쓸 수 있는지는 확인되지 않는다. **직접 입력해서 틀리는 것을 확인하는** 것이
이 프로그램의 핵심이다.

같은 사용자가 쓰는 `Jiri`(지역이해 암기 퀴즈)와 동일한 구조 — 빌드 없는 단일 HTML +
데이터 파일 + localStorage — 를 그대로 따른다. 검증된 틀이므로 새로 설계하지 않는다.

### 1.2 목표

- 시험범위 단어를 **일→한 / 한→일 / 예문 빈칸** 세 방향으로 훈련한다.
- 한→일은 반드시 **직접 써서** 확인한다. 보기에서 고르는 것으로는 시험에서 못 쓴다.
- **히라가나로 쓰는 단어인지 가타카나로 쓰는 단어인지**를 틀리면 틀렸다고 잡아 준다.
  시험범위가 가나 표기만 요구하므로, 이 구분이 곧 시험의 핵심 능력이다.
- 틀린 단어를 자동으로 추적해 맞을 때까지 반복 노출시킨다.
- 태블릿에서 **애플펜슬로 직접 써서** 답을 넣을 수 있게 한다. 시험이 손으로 쓰는
  시험이므로 연습도 손으로 쓰는 것이 맞다.

### 1.3 비목표 (이번 버전에서 하지 않는 것)

- 한자 → 읽기(요미가타) 전용 문제 유형 — 사용자가 시험 유형에서 제외했다.
  데이터에는 읽기(`kana`)를 모두 담아 두므로, 필요해지면 유형 하나 추가로 끝난다.
- 문법·독해·청해 문제
- 음성 재생(TTS)·발음 평가
- 다중 사용자 계정 / 서버 로그인 / 클라우드 동기화
- **한자 쓰기** — 시험범위가 히라가나·가타카나 표기만 요구한다. 한자는 읽으라고 보여 줄 뿐,
  쓸 수 있는지는 채점하지 않는다.
- **앱 내장 손글씨 인식기** — 아이패드 일본어 키보드의 `手書き` 모드가 이미 해 주는 일이다.
  손글씨 입력 자체는 **지원한다**(§6.4). 앱이 인식기를 따로 만들지 않을 뿐이다.
- AI 자동 문제 생성 — 데이터는 학습지 기반 수기·반자동 입력

### 1.4 성공 기준

- 시험범위 전체 단어에 대해 일→한, 한→일 두 유형이 모두 출제된다.
- 예문이 있는 단어는 빈칸 유형까지 출제된다.
- 오답 단어가 정답 처리될 때까지 반복 출제된다.
- 아이패드에서 애플펜슬로 쓴 가나가 그대로 입력된다 — 앱이 손글씨 입력을 방해하지 않는다.
- 가타카나로 써야 할 단어를 히라가나로 쓰면 오답으로 잡히고, 그 이유를 알려 준다.
- 한 세션(20문항)을 5분 안에 풀 수 있다.

## 2. 사용자

| 구분 | 설명 |
|---|---|
| 주 사용자 | 일본어 수업 수강생 본인 (단일 사용자) |
| 사용 환경 | 태블릿·휴대폰 우선(통학 중 학습), PC 브라우저도 지원 |
| 사용 시점 | 시험 2~3주 전부터 매일 10~20분 |

**핵심 사용자 스토리**

1. 시험범위 학습지를 넘겨주면 단어가 데이터로 들어가 있고, 앱을 열면 바로 시험이 시작된다.
2. 일본어 단어를 보고 뜻이 바로 안 떠오르는 단어를 골라내고 싶다.
3. 뜻을 보고 일본어를 **직접 써 보고** 맞았는지 확인하고 싶다.
4. 태블릿에서 애플펜슬로 `たべもの`라고 쓰면 그대로 들어가면 좋겠다. 시험도 손으로 쓰니까.
5. 히라가나로 쓰는 단어인지 가타카나로 쓰는 단어인지를 자꾸 헷갈리는데, 그걸 틀리면
   "틀렸다"가 아니라 **"가나 종류가 다르다"**고 짚어 줬으면 좋겠다.
6. 단어만 외우면 시험 문장에서 못 알아보니, 예문 속 빈칸으로도 확인하고 싶다.
7. 틀린 것만 모아서 다시 풀고 싶다.
8. 시험범위가 몇 과인지 골라서 그 과만 풀고 싶다.

## 3. 학습 콘텐츠 범위

### 3.1 현재 상태 — 미수령

**학습지·교재를 아직 받지 못했다.** 받는 즉시 아래 절차로 데이터를 만든다.
그때까지 이 문서의 범위 표는 비어 있다.

| 단원 | 코드 | 단어 수 | 예문 | 출처 쪽 |
|---|---|---|---|---|
| (수령 후 채움) | | | | |

### 3.2 데이터 확보 절차 (학습지 사진/PDF → 데이터)

1. 학습지·교재 스캔본을 받는다. **어느 쪽부터 어느 쪽까지가 시험범위인지** 함께 받는다.
2. 쪽마다 단어·읽기·뜻·예문을 읽어 `data/words.js`로 정리한다.
3. 스캔 품질 때문에 확신이 서지 않는 글자(촉음 `っ`, 장음 `ー`, 탁점 등)는
   추론한 근거와 함께 `docs/판독-정리.md`에 남기고, 항목에 `uncertain: true`를 단다.
   앱은 이 항목을 결과 화면에서 ⚠️로 표시해, 시험 전에 실물과 대조할 수 있게 한다.
4. 데이터 검증 스크립트로 누락(읽기 없음, 뜻 없음, 중복 단어)을 잡는다.

> **원칙**: 뜻과 표기는 **학습지 표현을 그대로** 쓴다. 사전에 더 나은 번역이 있어도
> 바꾸지 않는다. 시험 답안과 표현을 맞추는 것이 목적이기 때문이다.
> 학습지에 없는 뜻을 보충할 때는 `aliases`에만 넣고 대표 표기는 건드리지 않는다.

### 3.3 범위 밖

- 학습지 각주·읽을거리에만 나오는 단어는 넣지 않는다(`Jiri`와 같은 방침).
- 문법 설명, 활용표, 회화문 전체는 단어 데이터로 만들지 않는다.
  단, 회화문 중 **시험범위 단어가 들어간 문장**은 예문으로 가져온다.

## 4. 데이터 모델

### 4.1 단어(Word) 스키마

```jsonc
{
  "id": "l03_tabemono",         // 고유 ID (과_로마자)
  "unit": "003",                // 과(課) 코드 — 범위 선택 단위
  "pos": "명사",                 // 품사: 명사 | 동사 | い형용사 | な형용사 | 부사 | 표현
  "word": "食べ物",              // 표제어(학습지 표기 그대로) — 읽으라고 보여 주는 용도
  "kana": "たべもの",            // 가나 표기 — **한→일 유형의 정답 기준**. 모든 단어에 필수.
                                //   학습지가 가나로만 적어 놨으면 word와 같은 값
  "accent": 3,                  // 악센트 번호(선택, 교재에 있을 때만)
  "meaning": ["음식", "먹을 것"], // 한국어 뜻 — 첫 번째가 대표 뜻
  "aliases": ["먹거리"],          // 서답형에서 정답으로 인정할 다른 표현(선택)
  "jaAliases": [],              // 한→일에서 추가로 인정할 가나 표기.
                                //   표기가 둘 이상 통용될 때만 쓴다(§5.2의 엄격 채점 예외 창구)
  "examples": [                 // 예문 — 빈칸 유형의 재료
    {
      "ja": "好きな食べ物は何ですか。",
      "ko": "좋아하는 음식은 무엇입니까?",
      "form": "食べ物"           // 예문에 나타난 활용형(빈칸으로 파낼 정확한 문자열)
    }
  ],
  "tags": ["음식", "N5"],        // 오답 보기 선정·필터용(선택)
  "uncertain": false,           // 스캔 판독이 불확실하면 true
  "note": "학습지 12쪽"          // 출처 메모(선택)
}
```

**필수 필드**: `id`, `unit`, `word`, `kana`, `meaning`.
`kana`는 정답 기준이므로 학습지 표기를 **글자 하나까지 그대로** 옮긴다.
장음 `ー`, 촉음 `っ`, 탁점, 히라가나/가타카나 구분 전부 채점에 쓰인다.
`examples`가 없는 단어는 예문 빈칸 유형에서 자동 제외된다(검증에서 경고만, 오류 아님).

### 4.2 단원(Unit) 스키마

```jsonc
{ "code": "003", "title": "제3과 · 買い物", "pages": "10~13쪽" }
```

### 4.3 파일 구성

```
index.html          앱 전체 (UI + 퀴즈 엔진 + 로마자→가나 변환기)
data/words.js       단어 데이터 (WORDS 배열 + UNITS 배열)
build.py            데이터를 인라인한 단일 HTML 생성
일본어-단어시험.html   배포용 단일 파일 (build.py 산출물)
docs/PRD.md         이 문서
docs/판독-정리.md    스캔 판독이 불확실했던 항목과 근거
```

## 5. 문제 유형

세 유형 모두 한 단어 레코드에서 파생된다. 같은 단어가 세 유형에 모두 나올 수 있다.

### 5.1 유형 A — 일본어 → 한국어 뜻

읽고 이해하는 방향. 가장 쉬우므로 **기본 5지선다**로 두고, 서답형은 옵션으로 둔다.

- **화면**: `食べ物` (아래에 작게 `たべもの`)
  - 읽기 노출은 **토글 가능**. 끄면 한자 읽기까지 겸사겸사 확인된다.
- **질문**: "이 단어의 뜻은?"
- **보기**: 5개 (정답 1 + 오답 4)
- **오답 보기 규칙**
  1. **같은 품사**의 다른 단어 뜻에서 뽑는다 (동사 문제 → 다른 동사의 뜻).
  2. 부족하면 같은 과, 그다음 전체 풀에서 보충한다.
  3. 정답 단어의 다른 `meaning`·`aliases`와 겹치는 문구는 제외한다 — 정답이 둘이 되는 사고 방지.
  4. 보기 순서는 매번 셔플.
- **서답형 옵션**: 한국어 뜻은 표현이 사람마다 달라 자동 채점이 부정확하다.
  그래서 서답형을 켜면 **자가 확인 방식**으로 동작한다 —
  뜻을 떠올린 뒤 "확인"을 누르면 정답이 열리고, 맞았는지는 사용자가 O/X로 답한다.
  (`Jiri`의 '특징 떠올리기' 유형과 같은 구조)

### 5.2 유형 B — 한국어 뜻 → 일본어 (핵심 유형)

쓰는 방향. **반드시 직접 쓴다.** 시험 대비 효과가 가장 큰 유형이므로
기본 비중을 가장 높게 잡는다.

- **화면**: "음식" + 품사 표시(명사)
- **질문**: "일본어로 쓰면?"
- **입력**: 애플펜슬 손글씨 또는 타이핑. 입력 방식은 §6.4 참고.

#### 정답 기준은 `kana`(가나 표기)다

시험범위가 히라가나·가타카나 표기만 요구하므로, 한자를 쓸 수 있는지는 채점하지 않는다.

| 입력 | 판정 |
|---|---|
| `kana` 일치 | 정답 |
| `jaAliases` 중 하나와 일치 | 정답 |
| `word` 일치 (한자로 씀) | 정답 — 더 어려운 답을 틀렸다고 할 이유가 없다 |
| 가나 종류만 다름 | **오답**, 단 전용 안내(아래) |
| 그 밖 | 오답 |

#### 가타카나와 히라가나는 엄격히 구분한다

어느 쪽으로 쓰는 단어인지 아는 것이 이 시험의 핵심 능력이다.
따라서 `テレビ`를 `てれび`로 쓰면 **오답**이다.

다만 다른 오답과 똑같이 처리하지 않는다. 글자는 다 맞고 가나 종류만 틀렸을 때는
**"가나 종류가 다릅니다 — 이 단어는 가타카나로 씁니다"**라고 짚어 주고 다시 쓰게 한다.
아는 단어를 몰라서 틀린 것과, 표기 규칙을 헷갈려 틀린 것은 다시 봐야 할 지점이 다르다.
오답 노트에도 `가나 종류 오류`로 따로 표시해, 이 실수가 몰리는 단어를 볼 수 있게 한다.

#### 채점 정규화 — 여기까지만 관대하게 본다

1. 앞뒤·중간 공백 전부 제거
2. 전각/반각 통일 (`ｱ` → `ア`), 결합 탁점(`ｶﾞ` → `ガ`) 정규화 — 같은 글자의 폭 차이일 뿐이다
3. 문장 부호(`。` `、` `･`) 제거
4. 한국어 뜻 쪽 괄호 주석은 문제로 낼 때 미리 뗀다

**그 밖에는 학습지 표기와 글자 단위로 같아야 한다.** 장음 `ー`, 촉음 `っ`, 탁점,
작은 가나까지 전부 채점 대상이다. 표기가 둘 이상 통용되는 단어는 `jaAliases`에 적어 둔다.

> **v0.1에서 뒤집은 것**: 처음에는 가타카나를 히라가나로 통일해 비교하고
> 장음 `ー`와 모음 반복(`おかあさん`/`おかーさん`)을 같게 보려 했다.
> 시험이 **가나 표기 자체를 묻는다**는 것이 확인된 이상 둘 다 틀린 설계다.
> 정답을 오답으로 만들 걱정보다, 틀린 표기를 정답이라고 알려 줄 위험이 크다.

- **오타 허용은 하지 않는다.** `Jiri`는 편집거리 1까지 정답으로 봤지만,
  일본어는 촉음(`きって`/`きて`)·탁점(`かた`/`かだ`)·장음 한 글자가 다른 단어다.
  가나 표기가 곧 시험 내용인 이번 경우엔 더더욱 관대하게 볼 수 없다.
  대신 **"거의 맞았습니다 — 한 글자만 다릅니다"**라고 알려 주고
  **다시 쓰게** 한다(오답 기록은 남긴다).
- **피드백**: 가나 표기(크게) + 한자 표기(작게, 참고용) + 뜻 전체 + 예문 1개

### 5.3 유형 C — 예문 빈칸 채우기

문장 속에서 단어를 알아보는 훈련. `examples`가 있는 단어만 출제된다.

- **화면**: `好きな____は何ですか。` (아래에 한국어 해석)
- **질문**: "빈칸에 알맞은 말은?"
- **두 가지 모드**
  - **객관식(기본)**: 같은 품사 단어 4개를 오답 보기로. 문장 흐름상 명백히 안 맞는
    보기만 고르지 않도록, 같은 과·같은 품사를 우선한다.
  - **서답형(옵션)**: 유형 B와 같은 입력·채점을 쓴다.
- **활용형 처리**: 빈칸은 `form`(예문에 실제로 나타난 형태)을 파낸다.
  동사·형용사는 활용형이 표제어와 다르므로, 서답형에서는 `form`과 표제어
  **둘 다 정답으로 인정**한다(활용을 아직 안 배웠을 수 있으므로).
  판정은 유형 B와 같이 가나 기준이다.
- 해석은 기본으로 함께 보여 준다. 끄는 토글을 둔다.

### 5.4 출제 규칙

- 한 세션 안에서 같은 단어를 두 번 내지 않는다(오답 재출제 모드는 예외).
- 유형 비중 기본값: **B 50% · A 30% · C 20%**. 설정에서 유형별로 끌 수 있다.
- 선택한 범위에 예문 있는 단어가 부족하면 C 비중을 자동으로 낮춘다.

### 6.1 시작 화면 (세션 설정)

| 설정 | 옵션 | 기본값 |
|---|---|---|
| 범위 | 과(課) 단위로 켜고 끔 · 전체 선택/해제 | 전체 |
| 문제 유형 | A / B / C 각각 켜고 끔 | 셋 다 켬 |
| 문항 수 | 10 / 20 / 30 / 전체 | 20 |
| 출제 순서 | 랜덤 / 오답 우선 | 오답 우선 |
| 읽기 표시 | 유형 A에서 `kana` 노출 여부 | 켬 |
| 입력 방식 | 손글씨·OS 키보드 그대로 / 로마자 자동변환 / 화면 가나 자판 | 손글씨(변환 끔) |

### 6.2 퀴즈 진행 화면

- 상단: 진행률(`7 / 20`), 현재 점수
- 본문: 문제 + 입력창 또는 보기 5개
- 하단: 제출 · 힌트 · 건너뛰기(오답 처리)
- **힌트**: 유형 B는 두 단계로 나눈다 — 1단계는 **글자 수만**(`○○○○`),
  2단계에서 첫 글자를 연다(`た○○○`). 첫 글자를 열면 가나 종류까지 드러나기 때문에,
  그것만은 끝까지 스스로 떠올려 볼 기회를 한 단계 둔다. 유형 A의 힌트는 품사·태그.
  힌트를 쓴 문항은 정답이어도 "힌트 사용"으로 기록해 반복 대상에 남긴다.
- 키보드: `Enter` 제출·다음, `1~5` 보기 선택(PC)

### 6.3 결과 화면

- 총점, 정답률, 유형별 정답률, 과별 정답률
- 틀린 문항 목록: 단어 · 읽기 · 뜻 · 내가 쓴 답 · 정답
- "틀린 것만 다시 풀기" 버튼
- 판독 불확실(`uncertain`) 단어가 나왔으면 ⚠️로 모아서 표시

### 6.4 일본어 입력

시험이 손으로 쓰는 시험이므로, 연습도 손으로 쓰는 것을 기본으로 한다.

#### 1. OS 손글씨 입력 (기본 · 태블릿) — 앱이 만들 것은 없다

아이패드 일본어 키보드의 **`手書き` 모드**를 쓴다. 애플펜슬로 가나를 그리면 그대로
입력창에 들어간다. 인식은 OS가 한다.

앱 입장에서는 **평범한 텍스트 입력창**이므로, 할 일은 "방해하지 않는 것"뿐이다.
지켜야 할 것:

- 입력 이벤트를 가로채거나 키 입력을 직접 조립하지 않는다
- 자체 키보드를 강제로 띄우지 않는다 (`readonly` + 커스텀 입력 금지)
- 조합 중인 문자를 `compositionstart`~`compositionend` 사이에 건드리지 않는다
  (조합 중 값을 읽어 채점하면 반쪽짜리 가나로 오답 처리된다)
- 입력창 아래에 여백을 둬서, 손글씨 패널이 올라와도 문제와 입력창이 가리지 않게 한다
  (아이패드 `手書き` 패널은 화면 아래 절반가량을 차지한다)

> 이 방식은 **가나 종류를 사용자가 직접 정한다**는 점에서 이번 시험에 특히 잘 맞는다.
> `テ`를 그리면 `テ`가 들어간다. 앱이 히라가나·가타카나를 대신 골라 주지 않으므로
> §5.2에서 채점하려는 바로 그 능력을 흘리지 않는다.

#### 2. 로마자 → 가나 자동 변환 (PC·빠른 입력용)

펜이 없을 때, 또는 PC에서 빨리 돌릴 때 쓴다. 기본은 꺼 둔다.

- `tabemono` → `たべもの`. 헵번식·훈령식 둘 다 받는다(`shi`/`si`, `tsu`/`tu`, `fu`/`hu`, `ji`/`zi`).
- 촉음: 자음 겹침(`kitte` → `きって`), 발음(撥音) `n`/`nn` → `ん`,
  요음(`kya` → `きゃ`), 탁음·반탁음, 장음(`-` → `ー`).
- **가타카나 전환은 사용자가 직접 누른다.** 자동 판별하지 않는다 —
  어느 가나로 쓰는 단어인지 고르는 것이 곧 답의 일부이기 때문이다.
  히라가나 상태로 `terebi`를 치면 `てれび`가 되고, 그것은 §5.2대로 오답 처리된다.
- 가나가 그대로 들어오면 변환하지 않고 둔다(손글씨와 섞어 써도 안전).

#### 3. 화면 가나 자판 (보조)

50음도 팔레트 + 탁점·반탁점·작은 글자 버튼. 펜도 로마자도 여의치 않을 때의 대비책.

> **한자 변환(IME)은 구현하지 않는다.** 정답 기준이 가나 표기이므로 필요가 없다.
> **앱 내장 손글씨 인식기도 만들지 않는다.** OS가 이미 하고 있고, 자체 인식을 붙이면
> 오인식이 오답 노트를 오염시킬 위험만 늘어난다 — "내가 틀린 것"과 "기계가 못 읽은 것"이
> 구분되지 않으면 §6.5의 반복 학습 엔진 전체가 잘못된 기록 위에서 돌아간다.

### 6.5 오답 노트 / 반복 학습

`Jiri`에서 검증된 규칙을 그대로 쓴다.

- 단어별 상태 저장: `정답 횟수`, `오답 횟수`, `연속 정답`, `마지막 학습일`, `유형별 성적`,
  `가나 종류 오류 횟수`(§5.2)
- **가중 출제**: 최근에 틀린 단어, 오답 횟수가 많은 단어를 먼저 낸다.
- **졸업 규칙**: 연속 3회 정답 → `숙달` 표시, 출제 가중치 최소화.
  단, **유형별로 따로 센다** — 뜻은 아는데 못 쓰는 단어를 숙달로 넘기지 않기 위함이다.
- 진도 대시보드: 과별 `미학습 / 학습중 / 숙달` 개수
- **가타카나 오답 모아보기**: 가나 종류를 틀린 단어만 따로 묶어 보여 준다.
  이 실수는 단어를 몰라서가 아니라 표기 규칙이 안 잡혀서 나므로, 몰아서 보는 편이 낫다.

### 6.6 저장

- 학습 기록은 브라우저 `localStorage`에 저장 (단일 사용자, 서버 없음)
- 기록 JSON 내보내기 / 가져오기 / 초기화

## 8. 기술 스택

`Jiri`와 동일하다. 새로 정할 것이 없다.

- **프론트엔드**: HTML + 바닐라 JavaScript, 빌드 도구·의존성 없음
- **데이터**: `data/words.js` — 객체 하나 넣으면 단어 하나 추가
- **저장**: `localStorage`
- **배포**: `python3 build.py` 로 데이터까지 인라인한 **단일 HTML**을 만들고,
  태블릿용으로는 그 파일을 Artifact 링크로 발행한다
  (아이패드는 내려받은 HTML을 브라우저로 여는 길이 막혀 있어 파일 방식이 안 통한다).

## 11. 전제 및 확인 필요 사항

**전제 (별도 지시 없으면 이대로 진행)**

- 단일 사용자, 로그인 없음, 기록은 브라우저에 저장한다.
- 뜻·표기는 학습지 표현을 그대로 쓴다.
- **정답 기준은 가나 표기다.** 한자 쓰기는 채점하지 않는다.
- **히라가나·가타카나 구분은 채점한다.** 시험범위가 가나 표기만 요구하는 만큼,
  어느 가나로 쓰는지가 사실상 시험 내용이다.
- 손글씨는 OS 기능(아이패드 `手書き`)으로 받는다. 앱은 인식기를 만들지 않는다.
- 한자 → 읽기 전용 유형은 만들지 않는다. 단, `kana`는 모든 단어에 채워 둔다.
- 음성은 넣지 않는다.

**받아야 하는 것**

1. 학습지·교재 사진 또는 PDF
2. **시험범위** — 몇 과부터 몇 과까지, 또는 몇 쪽부터 몇 쪽까지
3. 시험 날짜 (반복 일정을 잡을 때 참고)

**확인이 필요한 것**

1. 교재에 예문이 실려 있는가? 없으면 유형 C는 출제 대상이 크게 줄거나 빠진다.
2. **한자를 읽을 줄은 알아야 하는가?** 쓰기는 안 해도 되는 것이 확인됐지만,
   학습지가 단어를 한자로 적어 놨다면 유형 A에서 한자를 그대로 보여 줘야 한다.
   학습지가 처음부터 가나로만 적혀 있다면 `word`와 `kana`가 같아져 스키마가 더 단순해진다.
3. 가타카나 단어가 범위에 얼마나 있는가? 많다면 §12의 "가나 종류 고르기" 유형을
   v1에 넣는 편이 낫다.

> ~~시험에서 한자로 쓸 것을 요구하는가~~ → **해결됨(v0.2)**: 가나만 쓰면 된다.

## 12. 향후 확장 (v2 이후)

- **가나 종류 고르기 유형** — "이 단어는 히라가나·가타카나 중 어느 쪽으로 쓰나?" 2지선다.
  가나 종류 오답이 많이 쌓이면 그 단어들만 모아 짧게 돌리는 용도. 데이터 추가가 전혀 필요 없다.
- 한자 → 읽기 유형 추가 (데이터는 이미 준비되어 있음)
- 음성 재생 — 단어 발음 듣고 쓰기(받아쓰기) 유형
- 간격 반복(SM-2) 복습 일정
- 활용형 훈련 — ます형·て형·た형 변환 문제
- 학습 기록 통계 그래프
- 시험 직전용 "전 범위 모의고사" 모드 (시간 제한 + 유형 혼합)
